# v1.5 — Feedback-height stacking and video encoder fix

The previous timed expert descended to a *fixed* Z-joint setpoint (`0.08 m`)
without observing the actual boxes. It could side-push the orange target and
always sent the release command even when not aligned.

The replacement `run_expert.py` is **simulation-only**, using privileged Gazebo
object poses and gantry joint positions. It lifts completely *before* lateral
movement, aligns box centers, computes desired upper-box world height from the
lower-box world pose, descends gradually, and gates release on several stable
samples. It aborts rather than knowingly release at an incorrect height.

For nominal upright dimensions, lower top = `lower_z + 0.04 m` and the upper
center target = `lower_z + 0.04 + 0.03 + 0.006 = lower_z + 0.076 m`.
This deliberately leaves a 6 mm air gap to settle under gravity.

This is not a verified physics-successful stacking controller. The Gazebo model
may still exhibit slip, controller lag, or collisions. Use `inspect_stack.py`
and the MP4 to verify. Ground-truth topics must **not** be provided to a
learned visual VLA at deployment.

## Apply

From repository root:

```bash
unzip -o ~/Downloads/conveyor-belief-vla-v1.5-height-video-patch.zip
# Files are bind-mounted; no Docker image rebuild needed.
```

## Recover the already-captured 219-frame video

```bash
bash scripts/encode_existing_demo.sh data/demo_20261106T140150Z_500751_26172
xdg-open data/latest_demo/demonstration.mp4
```

If FFmpeg reports frames missing/unreadable, diagnose with:

```bash
ls -ld data/demo_20261106T140150Z_500751_26172/frames
ls -l data/demo_20261106T140150Z_500751_26172/frames/frame_000000.png
```

If root permissions are the cause, `sudo chmod -R a+rX data/demo_...`
can restore read access. Do not rerun the demonstration merely to encode frames.

## Test the fixed expert

```bash
bash scripts/run_demo_video.sh 0.0
cat data/latest_demo/expert.log
cat data/latest_demo/stack_report.txt
xdg-open data/latest_demo/demonstration.mp4
```

Only try `bash scripts/run_demo_video.sh 0.04` once the stationary stacking
geometry and stability are confirmed. Video is recorded at 20 fps (camera's
nominal rate), so it is a useful diagnostic but not a force-contact measurement.

## What good logs look like

The phases should include `lift`, `align_above_target`,
`descend_with_feedback`, `release`, `retract`, `complete`. If conditions aren't
met, the expert prints `ABORT` in `expert.log` and does **not** issue detach.

If missing pose topics cause an abort, check:

```bash
docker compose exec tools bash -c \
  'source /opt/ros/jazzy/setup.bash && ros2 topic list | grep /simulation/'
```

The patch contains the world PosePublisher and `config/bridge.yaml` from the
previous v1.3 diagnostics patch so it can be applied directly over v1.2.
